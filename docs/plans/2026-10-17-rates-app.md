# نرخ v1 Implementation Plan

> Steps use checkbox (`- [ ]`) syntax for tracking. Execute task by task, in order.

**Goal:** A working installable web app showing live toman prices (home board, tabs, detail
sheet with real charts and calculator) plus price alerts with push notifications.

**Architecture:** One small Node server polls Nobitex and tgju every 60 s, keeps the latest
quotes in memory, records snapshots and alerts in SQLite, and serves both a JSON API and the
static web app from `public/`. The web app is the approved prototype split into plain ES
modules, with its fake data replaced by API calls.

**Tech Stack:** Node 24 (ES modules, `node:http`, `node:sqlite`, `node:test`, global `fetch`),
`web-push` (only dependency), vanilla HTML/CSS/JS in the browser.

**Spec:** `docs/specs/2026-10-17-rates-app-design.md`

## Global Constraints

- All JavaScript. No framework, no bundler, no TypeScript. Browser code is `<script type="module">`.
- Only runtime dependency: `web-push`. Everything else from Node's standard library.
- Prices shown in **toman** = source rial ÷ 10. Gold ounce (`goz`) and silver ounce (`soz`) are shown in **dollars** (tgju already gives USD).
- Persian digits via `Intl.NumberFormat('fa-IR')`; Jalali dates via `Intl.DateTimeFormat('fa-IR-u-ca-persian', …)`; page is `dir="rtl" lang="fa"`.
- Every price shows its own "updated X ago", from that item's source timestamp, not the poll time.
- tgju `ts` is Tehran local time with no zone: parse as `ts.replace(' ', 'T') + '+03:30'`.
- tgju `d` is unsigned; sign comes from `dt`: `'high'` → positive, `'low'` → negative, anything else → 0. Same for `dp`.
- Look and copy come from `prototype/home-apple.html` (approved). Keep its CSS tokens, Persian labels, icons and motion.
- Commit messages: `<type>: <description>`, no AI attribution trailers.
- Server listens on `PORT` env var, default `3000`.

## Item catalog (ids reused from the prototype)

| id | source | key | tab |
|---|---|---|---|
| usd eur gbp aed try iqd cny | tgju | `price_dollar_rl price_eur price_gbp price_aed price_try price_iqd price_cny` | ارز |
| btc eth usdt doge sol xrp | nobitex | `btc eth usdt doge sol xrp` (vs `rls`) | رمزارز |
| g18 g24 msq emami bahar nim rob gerami goz | tgju | `geram18 geram24 mesghal sekee sekeb nim rob gerami ons` | طلا و سکه |
| s999 s925 soz | tgju | `silver_999 silver_925 silver` | نقره |

Home board: `g18`, `usd`, `btc`.

Coin bubble: `intrinsic = g18 × weight × 900/750`, weights in grams: emami 8.133, bahar 8.133,
nim 4.066, rob 2.033, gerami 1.011. `bubblePct = (price / intrinsic − 1) × 100`.

## Review Focus

1. **A source is down or returns junk** (timeout, HTML error page, missing key): the server keeps the last good quote for each item and keeps serving; it never crashes or blanks the whole list. Tested in Task 3.
2. **One item is stale at the source** (iqd was 8 days old): its row shows the true age ("۸ روز پیش"), others are unaffected. Tested in Task 2 (timestamp parsing) and Task 5 (`ago()`).
3. **Price wobbles around an alert target**: a repeat alert fires once per crossing, never every minute. Tested in Task 7.
4. **Bad alert input from the browser** (unknown item, negative/NaN/huge target, bad direction, missing device id): rejected with 400, nothing stored. Tested in Task 8.
5. **Calculator input in Persian or Arabic digits with separators** (`۱۲٬۵۰۰`, `١٢٥٠٠`): converts correctly; garbage gives an empty result, not `NaN`. Tested in Task 5.

### Task 7: Alert logic and storage

**Files:**
- Create: `server/alerts.js`, `tests/alerts.test.js`
- Modify: `server/db.js` (alerts table)

**Interfaces:**
- Produces:
  - Table `alerts(id TEXT PRIMARY KEY, device TEXT, item TEXT, direction TEXT, target REAL, repeat INTEGER, enabled INTEGER, armed INTEGER, firedAt INTEGER, createdAt INTEGER)`.
  - `evaluateAlert(alert, price, now): {fire: boolean, alert}`: pure, returns a new object.
  - `createAlertStore(db)`: `list(device)`, `create(device, {item, direction, target, repeat})`, `update(device, id, patch)`, `remove(device, id)`, `checkAll(quotes, now): Alert[] /* fired */`. Every method is scoped to `device`.

Rules for `evaluateAlert` (`hit = direction === 'above' ? price >= target : price <= target`):
- not enabled → no fire, unchanged.
- `hit && armed` → fire; `armed = false`, `firedAt = now`, `enabled = repeat`.
- `!hit && !armed && repeat` → `armed = true` (re-arms only after the price goes back across).
- re-enabling through `update` sets `armed = true`.

- [ ] **Step 1: Write the failing tests:**
  - `'above alert fires when the price reaches the target'`: target 270000, price 270000 → fire.
  - `'once alert turns itself off after firing'`: → `enabled === false`.
  - `'repeat alert does not fire twice while price stays above'`: 270100, then 270500 → second `fire === false`.
  - `'repeat alert fires again after going back below and up'`: 270100 → 268000 → 270000 → fires twice total.
  - `'below alert works the other way'`.
  - `'evaluateAlert does not mutate its input'`.
  - `'checkAll only touches the item it is about'` and `'list is scoped to the device'`.
- [ ] **Step 2:** FAIL → **Step 3:** implement → **Step 4:** PASS. Commit `feat: price alert logic`.

### Task 8: Alerts API and web push

**Files:**
- Create: `server/push.js`, `tests/alerts-api.test.js`
- Modify: `server/app.js`, `server/index.js`, `package.json` (`npm i web-push`), `.gitignore` (`.env`)

**Interfaces:**
- Consumes: `createAlertStore`, poller `onQuotes`.
- Produces:
  - Device id: client sends header `X-Device: <uuid v4>`; requests without a valid uuid → 400.
  - `GET /api/alerts`, `POST /api/alerts`, `PATCH /api/alerts/:id`, `DELETE /api/alerts/:id`.
  - `GET /api/push/key` → `{key}`; `POST /api/push/subscribe` stores the subscription JSON for the device.
  - `createPush({db, publicKey, privateKey}): {notify(device, payload): Promise<void>}`. A `410`/`404` from the push service deletes that subscription.
  - VAPID keys read from env `VAPID_PUBLIC`, `VAPID_PRIVATE`; if missing, `index.js` generates a pair once and writes it to `.env` (git-ignored) so subscriptions survive restarts.
  - Wiring: `onQuotes` → `alerts.checkAll` → `push.notify` for each fired alert with `{title: '<item name>', body: '<قیمت> رسید به <price>'}`.
- Validation (Review Focus 4): `item` in catalog, `direction` in `above|below`, `target` finite and `0 < target < 1e15`, `repeat` boolean, body ≤ 1 KB.

- [ ] **Step 1: Write the failing tests:**
  - `'creates and lists an alert for the device'`.
  - `'another device cannot see or delete it'` → list empty, DELETE → 404.
  - `'rejects bad alert input'`: each of unknown item, `direction:'up'`, `target:-1`, `target:'abc'`, missing `X-Device` → 400 and table still empty.
  - `'fired alert triggers a push to that device'`: fake `push.notify` records calls; poll with price over target → 1 call.

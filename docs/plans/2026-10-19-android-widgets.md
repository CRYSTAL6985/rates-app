# نرخ Android app + widgets Implementation Plan

**Goal:** An Android APK of نرخ (Capacitor shell around the existing web app) with a favourites widget, a single-price widget, and background alert notifications.

**Architecture:** Capacitor 8 loads the نرخ server's URL in a WebView, so the web app stays as is. The web app mirrors favourites and its device id into Capacitor Preferences (SharedPreferences `CapacitorStorage`). Native Kotlin (RemoteViews widgets + a WorkManager worker) reads those, calls the same JSON API, and draws the widgets / posts alert notifications.

**Tech Stack:** Capacitor 8.5 (`@capacitor/core`, `cli`, `android`, `preferences` 8.0), Kotlin, AndroidX WorkManager, JUnit 4 + `org.json:json` for JVM tests, Node test runner for the JS.

**Spec:** `docs/specs/2026-10-19-android-widgets-design.md`

## Global Constraints

- App id `ir.nerkh.app`, name «نرخ» (development values; final before publishing).
- One server address, from env `NERKH_SERVER` at sync time (e.g. `http://192.168.1.5:3000`); missing → the sync fails loudly. Native code reads it back from the synced `assets/capacitor.config.json` (`server.url`), never a second copy.
- Plain http allowed only because the dev server is http; note it as a pre-publish item.
- Widgets: Persian digits, RTL, dark/light from the system, same rules as `public/format.js` (`formatPrice`, `formatPct`, `ago`), stale = older than 6 h (red).
- Background refresh: WorkManager periodic, 15 min (Android's minimum), network required. Also on favourites change and app resume.
- Widget/notification tap opens `<server>/?item=<id>` (existing web handling in `public/alerts.js`).
- No changes to server behaviour. Web behaviour in a normal browser unchanged.
- Every Kotlin file is explained to the user as it lands (he's new to Kotlin).

## Review Focus

- Server unreachable (PC off, other Wi-Fi): widgets keep last prices and show their real age, no crash, no blank widget. → Task 4 test `cache survives a failed fetch`.
- App never opened (no favourites, no device id in Preferences): favourites widget shows server `top` defaults; alert check is skipped, not crashing. → Task 4 test `missing favourites fall back to top`, Task 6 test `no device id means no alert call`.
- A favourite the server no longer lists: dropped from the widget, like the app does. → Task 3 test `unknown favourite ids are skipped`.
- Same `firedAt` seen twice (worker runs again, phone reboots): one notification only. → Task 6 test `an alert fires a notification once`.
- Notification permission denied (Android 13+): alerts screen says so in Persian, nothing throws. → Task 2 test `denied permission returns the message`.
